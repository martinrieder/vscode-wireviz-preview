## The test script — `test-schema.js`

`test-schema.js` validates WireViz YAML files against the JSON schema in
[`../schemas/wireviz-schema.json`](../schemas/wireviz-schema.json) using
[AJV](https://ajv.js.org/) (draft-07) and [`js-yaml`](https://github.com/nodeca/js-yaml).

It loads every `.yml`/`.yaml` file in a given examples directory, parses the
YAML, and validates the resulting object against the schema. A file that
parses and validates cleanly is a pass (`✓`); a parse failure or any schema
violation is a fail (`✗`), with the offending `instancePath` and `message`
printed for each error. The script exits non-zero if any file fails.

### Usage

```sh
# Validate all YAML files in a directory against the schema (defaults shown)
node test/test-schema.js --path <examples-dir> --schema ../schemas/wireviz-schema.json

# Show help
node test/test-schema.js --help

# Only print failures
node test/test-schema.js --quiet
```

Options:

| Flag       | Description                                                              | Default                                       |
|------------|--------------------------------------------------------------------------|-----------------------------------------------|
| `--path`   | Directory containing WireViz YAML files to validate                      | `../../WireViz/examples` (relative to script) |
| `--schema` | Path to the JSON schema file                                             | `../schemas/wireviz-schema.json`              |
| `--quiet`  | Only show failures, not successes                                        | off                                            |
| `--help`   | Show help and exit                                                       | —                                              |

> The valid WireViz example files (the "known-good" set the schema must
> accept) live in the upstream WireViz repository and are referenced by the
> script's default `--path`. They are **not** copied into this repository.
> The files present here are exclusively the **negative** fixtures below.

## Intentionally broken YAML fixtures

The `ex*.yml` files in this directory are **deliberately malformed** and are
named so they can be identified as invalid-syntax test cases. Each one is
derived from a valid WireViz example, introduces exactly one error category,
and states that category in a header comment. They must NOT be used as real
WireViz input.

Two layers of validation are exercised:

1. **YAML syntax layer** — rejected by any YAML parser before the schema (or
   WireViz) runs.
2. **WireViz semantic layer** — parse as valid YAML but are rejected by
   WireViz itself (and/or the schema) when it builds the harness.

### YAML syntax errors (caught at parse time)

These are rejected by `js-yaml` (and PyYAML) before the schema is applied, so
`test-schema.js` reports them as parse errors.

| File | Error category | Result |
|------|----------------|--------|
| `ex01-broken-indentation.yml` | Inconsistent/under-indented mapping keys | YAML `ScannerError` |
| `ex02-unclosed-flow-sequence.yml` | Missing closing `]` in a flow sequence | YAML `ParserError` |
| `ex03-tab-indentation.yml` | Tab characters used for indentation | YAML `ScannerError` |
| `ex05-undefined-anchor.yml` | Reference to an anchor that was never defined (`*con_power_f`) | YAML `ComposerError` |

### WireViz semantic errors (valid YAML, rejected by WireViz)

These parse as YAML but fail when WireViz interprets them. The schema catches
the structural ones; referential-integrity errors (undeclared connector
references) are not expressible in JSON Schema and are only caught at WireViz
runtime.

| File | Error category | Schema result | WireViz result |
|------|----------------|---------------|----------------|
| `ex04-duplicate-keys.yml` | Same cable designator `W1` declared twice | rejected (duplicate mapping key parse error) | WireViz error (IndexError) |
| `ex06-outdated-attribute.yml` | `pinout` (renamed to `pinlabels` in v0.2) | rejected (`additionalProperties`) | WireViz `ValueError` |
| `ex07-unknown-color-code.yml` | `color_code: ZZZ` is not a known code | rejected (`enum`) | WireViz `Exception: Unknown color code` |
| `ex08-undefined-connector-ref.yml` | A connection references connector `X3` that is never declared | **accepted** (referential integrity is not expressible in JSON Schema) | WireViz `Exception` |

Each broken file carries a header comment naming its error category and the
valid example it was derived from.

## Verification

The broken set was confirmed to fail at the layer indicated above: YAML
parse errors via `js-yaml`/PyYAML for the syntax group, and WireViz runtime
