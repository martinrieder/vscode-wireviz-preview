# WireViz YAML Test Examples

CONTENT GENERATED BY AI

A collection of WireViz YAML examples used for testing YAML validation and preview
behaviour in this extension.

## Layout

```
examples/wireviz/
├── *.yml            # Valid reference examples (transferred from the WireViz repo)
└── invalid/         # Intentionally broken examples for invalid-syntax testing
    └── *.yml
```

## Valid reference examples

The `*.yml` files in this directory are the example `.yml` files from the
[WireViz](https://github.com/wireviz/wireviz) `examples/` directory
(`demo01`, `demo02`, `ex01`–`ex14`). Only the YAML sources were transferred; the
generated artifacts (`.gv`, `.html`, `.png`, `.svg`, `.bom.tsv`) and the
`resources/` assets were intentionally omitted.

These are the baseline "known-good" files. Every one of them parses cleanly as
YAML and renders under WireViz 0.4. They exercise the common WireViz constructs:

| File     | Highlights |
|----------|------------|
| demo01   | D-Sub / Molex, color_code, shield |
| demo02   | metadata, templates, multiple template merges |
| ex01     | basic color_code + crossover |
| ex02     | YAML anchors and merge keys (`<<: *alias`) |
| ex03     | bundle with looping colors |
| ex04     | ferrule `.` auto-generation shorthand |
| ex05/ex06| daisy chains via templates |
| ex07     | `hide_disconnected_pins`, `pincount` |
| ex08     | `image`, `pins` + `pinlabels`, shield color |
| ex09     | large pincount, custom pin numbering |
| ex10     | T568A crossover cable |
| ex11–ex14| advanced `.` designator autogeneration, splices, mates |

## Intentionally broken examples

The files under `invalid/` are **deliberately malformed** and are named so they
can be identified as invalid-syntax test cases. Each one is derived from a valid
example, introduces exactly one error category, and states that category in a
header comment. They must NOT be used as real WireViz input.

Two layers of validation are exercised:

1. **YAML syntax layer** — rejected by any YAML parser before WireViz runs.
2. **WireViz semantic layer** — parse as valid YAML but are rejected by WireViz
   itself when it builds the harness.

### YAML syntax errors (caught at parse time)

| File | Error category | Result |
|------|----------------|--------|
| `ex01-broken-indentation.yml` | Inconsistent/under-indented mapping keys | YAML `ScannerError` |
| `ex02-unclosed-flow-sequence.yml` | Missing closing `]` in a flow sequence | YAML `ParserError` |
| `ex03-tab-indentation.yml` | Tab characters used for indentation | YAML `ScannerError` |
| `ex05-undefined-anchor.yml` | Reference to an anchor that was never defined (`*con_power_f`) | YAML `ComposerError` |

### WireViz semantic errors (valid YAML, rejected by WireViz)

These parse as YAML but fail when WireViz interprets them. They are useful for
testing how the extension surfaces non-YAML WireViz failures.

| File | Error category | Result |
|------|----------------|--------|
| `ex04-duplicate-keys.yml` | Same cable designator `W1` declared twice | WireViz error (IndexError) |
| `ex06-outdated-attribute.yml` | `pinout` (renamed to `pinlabels` in v0.2) | WireViz `ValueError` |
| `ex07-unknown-color-code.yml` | `color_code: ZZZ` is not a known code | WireViz `Exception: Unknown color code` |
| `ex08-undefined-connector-ref.yml` | A connection references connector `X3` that is never declared | WireViz `Exception` |

## Verification

The valid set was confirmed to parse with PyYAML, and the broken set was
confirmed to fail at the layer indicated above (PyYAML for the syntax group;
`wireviz` for the semantic group, against WireViz 0.4.1).

Re-check from this directory:

```sh
# YAML syntax check (valid set must pass, syntax-broken set must fail)
python3 -c "import yaml,glob;[list(yaml.safe_load_all(open(f))) for f in glob.glob('*.yml')]"

# WireViz semantic check (semantic-broken set must raise)
python3 -c "from wireviz.wireviz import parse; parse('invalid/ex06-outdated-attribute.yml')"
```
