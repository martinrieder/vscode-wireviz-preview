## Objective
Determine if the `redhat.vscode-yaml` extension provides an API that can be used to get the YAML syntax tree and node at cursor position, to avoid adding `js-yaml` as a dependency.

---

## Research Findings

### Available API Documentation

Based on the [Extension API Wiki](https://github.com/redhat-developer/vscode-yaml/wiki/Extension-API), the redhat-yaml extension provides the following APIs:

1. **`registerContributor`** - Register a schema contributor
   - Purpose: Associate YAML files with schemas based on file content
   - Use case: Dynamic schema assignment
   - Not relevant for our use case

2. **`modifySchemaContent`** - Modify schemas in memory
   - Purpose: Add/delete/modify schema properties
   - Use case: Dynamic schema modification
   - Not relevant for our use case

### Missing APIs

The documented API does **NOT** include:
- `parseYAML` function
- `getNodeAtPosition` function
- Any syntax tree access functions
- Any document parsing functions

### Source Code Analysis

Looking at the [vscode-yaml GitHub repository](https://github.com/redhat-developer/vscode-yaml), the extension is primarily a **client** for the [yaml-language-server](https://github.com/redhat-developer/yaml-language-server).

The extension:
1. Communicates with the yaml-language-server via LSP (Language Server Protocol)
2. Provides schema association features
3. Does NOT expose the language server's parsing capabilities to other extensions

### Language Server Capabilities

The yaml-language-server **does** have the capability to:
- Parse YAML documents
- Provide AST (Abstract Syntax Tree)
- Support `textDocument/documentSymbol` requests
- Support `textDocument/semanticTokens` requests

However, these capabilities are **NOT exposed** through the extension's public API.

---

## Conclusion

### Can we use redhat-yaml for syntax tree access?

**NO** - The redhat-yaml extension does NOT provide an API to:
- Get the YAML syntax tree
- Get the node at a specific position
- Parse YAML documents programmatically

### What are our options?

#### Option 1: Direct yaml-language-server Communication
We could potentially communicate directly with the yaml-language-server if it's running, but:
- This is complex and fragile
- The server may not be running
- No official API for this
- Would require implementing LSP client code

#### Option 2: Use VS Code's Built-in YAML Support
VS Code has built-in YAML language support (since version 1.35+), but:
- No public API for syntax tree access
- Only provides basic syntax highlighting

#### Option 3: Regex-Based Extraction (Recommended)
Since we cannot add `js-yaml` as a dependency, and redhat-yaml doesn't provide the needed API, we should use **regex-based extraction** as the primary method.

**Advantages:**
- No dependencies required
- Works with any YAML file
- Fast and lightweight
- Under our control

**Disadvantages:**
- Less accurate than full AST parsing
- May miss edge cases
- Requires maintenance for WireViz-specific patterns

### Designator Extraction Strategy

Since redhat-yaml cannot be used for syntax tree access, we will use a **pure regex-based approach**:

```typescript
// src/utils/designatorExtractor.ts

/**
 * Extracts designators from YAML at cursor position using regex patterns
 * 
 * Handles:
 * - Direct keys (X1:, W1:, F:)
 * - Connection set items (- X1: [1-4])
 * - Multi-line connection sets
 * - Nested structures
 */
export function extractDesignators(
    doc: vscode.TextDocument,
    position: vscode.Position
): string[] {
    const line = doc.lineAt(position.line).text;
    const lineNumber = position.line;
    
    // Pattern 1: Direct key at start of line or after whitespace
    // Matches: "X1:", "  X1:", "- X1:"
    const keyPattern = /^(\s*(?:-\s*)?)([A-Za-z][A-Za-z0-9_.]*)\s*:/;
    const keyMatch = line.match(keyPattern);
    if (keyMatch) {
        return [keyMatch[2]];
    }
    
    // Pattern 2: Connection set - extract all designators from current line
    // Matches: "- X1: [1-4]" or "- W1: [1-4]"
    const connectionPattern = /-\s*([A-Za-z][A-Za-z0-9_.]*)\s*:/g;
    let matches: RegExpExecArray | null;
    const connectionDesignators: string[] = [];
    
    while ((matches = connectionPattern.exec(line)) !== null) {
        connectionDesignators.push(matches[1]);
    }
    
    if (connectionDesignators.length > 0) {
        return connectionDesignators;
    }
    
    // Pattern 3: Check if we're in a connections block
    if (isInConnectionsBlock(doc, lineNumber)) {
        return extractAllConnectionDesignators(doc, lineNumber);
    }
    
    // Pattern 4: Check for designator references in pin mappings
    // Matches: "X1: [1-4]" within a connection
    const refPattern = /([A-Za-z][A-Za-z0-9_.]*)\s*:\s*\[/g;
    const refDesignators: string[] = [];
    let refMatch: RegExpExecArray | null;
    
    while ((refMatch = refPattern.exec(line)) !== null) {
        refDesignators.push(refMatch[1]);
    }
    
    if (refDesignators.length > 0) {
        return refDesignators;
    }
    
    return [];
}

/**
 * Checks if a line is within a connections block
 */
function isInConnectionsBlock(doc: vscode.TextDocument, lineNumber: number): boolean {
    // Look backwards for "connections:" line
    for (let i = lineNumber; i >= Math.max(0, lineNumber - 20); i--) {
        const line = doc.lineAt(i).text.trim();
        if (line === 'connections:' || line === '- connections:') {
            return true;
        }
        // Stop if we reach a top-level key
        if (line.length > 0 && !line.startsWith('-') && !line.startsWith(' ') && !line.startsWith('\t')) {
            break;
        }
    }
    return false;
}

/**
 * Extracts all designators from a connection set
 * A connection set is a YAML array item containing multiple connection entries
 */
function extractAllConnectionDesignators(doc: vscode.TextDocument, lineNumber: number): string[] {
    const designators: Set<string> = new Set();
    
    // Find the start of the connection set (line starting with "-")
    let startLine = lineNumber;
    while (startLine >= 0) {
        const line = doc.lineAt(startLine).text;
        const trimmed = line.trim();
        
        // Found the start of the connection set
        if (trimmed.startsWith('-') && trimmed !== '-') {
            break;
        }
        
        // Stop if we hit a non-connection line
        if (trimmed.length > 0 && !trimmed.startsWith(' ') && !trimmed.startsWith('\t')) {
            return [];
        }
        
        startLine--;
    }
    
    // Collect all lines in this connection set
    const connectionLines: string[] = [];
    for (let i = startLine; i < doc.lineCount; i++) {
        const line = doc.lineAt(i).text;
        const trimmed = line.trim();
        
        // Connection set items start with "-"
        if (trimmed.startsWith('-') && trimmed !== '-') {
            connectionLines.push(line);
        }
        // Continuation lines (indented)
        else if (trimmed.length > 0 && (trimmed.startsWith(' ') || trimmed.startsWith('\t'))) {
            connectionLines.push(line);
        }
        // End of connection set
        else if (trimmed.length > 0) {
            break;
        }
    }
    
    // Extract designators from all lines
    const pattern = /-\s*([A-Za-z][A-Za-z0-9_.]*)\s*:/g;
    for (const line of connectionLines) {
        let match: RegExpExecArray | null;
        while ((match = pattern.exec(line)) !== null) {
            designators.add(match[1]);
        }
    }
    
    return Array.from(designators);
}
```

## WireViz-Specific Patterns

### Document Structure
```yaml
# Top-level sections
connectors:      # Map of connector definitions
  X1:           # Connector designator
    type: ...
    
cables:         # Map of cable definitions  
  W1:           # Cable designator
    gauge: ...

connections:    # Array of connection sets
  -             # Connection set 1
    - X1: [1-4] # Designator reference
    - W1: [1-4]
    - X2: [1-4]
  -             # Connection set 2
    - X1: [5-8]
    - W2: [1-4]
```

### Designator Patterns

1. **Connector/Cable Definitions**: `X1:`, `W1:`, `F.`
   - Pattern: `^[A-Za-z][A-Za-z0-9_.]*\s*:`
   - Context: Direct child of `connectors:` or `cables:` section

2. **Connection References**: `X1: [1-4]`
   - Pattern: `[A-Za-z][A-Za-z0-9_.]*\s*:\s*\[`
   - Context: Within a connection set (array item under `connections:`)

3. **Designator with Pin Range**: `X1: [1-4, 6-8]`
   - Pattern: Same as #2, but pin range can be complex

```typescript
function extractDesignators(doc: vscode.TextDocument, position: vscode.Position): string[] {
    const line = doc.lineAt(position.line);
    const lineText = line.text;
    const lineNumber = position.line;
    
    // Get the current section (connectors, cables, connections, etc.)
    const currentSection = getCurrentSection(doc, lineNumber);
    
    switch (currentSection) {
        case 'connectors':
        case 'cables':
            return extractDefinitionDesignator(lineText);
        
        case 'connections':
            return extractConnectionDesignators(doc, lineNumber);
        
        default:
            return extractAnyDesignator(lineText);
    }
}

function getCurrentSection(doc: vscode.TextDocument, lineNumber: number): string | null {
    // Look backwards for section headers
    for (let i = lineNumber; i >= 0; i--) {
        const line = doc.lineAt(i).text.trim();
        
        if (line === 'connectors:' || line === 'cables:' || line === 'connections:') {
            return line.replace(':', '');
        }
        
        // Stop at top-level
        if (line.length > 0 && !line.startsWith(' ') && !line.startsWith('\t')) {
            break;
        }
    }
    return null;
}
```

### 3. Caching for Performance
```typescript
// Cache designators per line to avoid re-parsing
let designatorCache: Map<number, string[]> = new Map();
let cacheDocVersion: number = -1;

function extractDesignatorsCached(doc: vscode.TextDocument, position: vscode.Position): string[] {
    const lineNumber = position.line;
    
    // Invalidate cache if document changed
    if (doc.version !== cacheDocVersion) {
        designatorCache.clear();
        cacheDocVersion = doc.version;
    }
    
    // Check cache
    if (designatorCache.has(lineNumber)) {
        return designatorCache.get(lineNumber)!;
    }
    
    // Extract and cache
    const designators = extractDesignators(doc, position);
    designatorCache.set(lineNumber, designators);
    
    return designators;
}
```
